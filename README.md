# М.Видео — ИИ для заполнения характеристик товаров

Продуктовый бриф для чекпоинта хакатона 15 октября 2026 года. Проект извлекает атрибуты из названия, описания и полей продавца, приводит значения к единому виду и показывает источник, метод, уверенность и статус каждого значения. Изображения не используются.

**[Открыть продуктовый бриф (PDF)](product-brief-checkpoint.pdf)** — 10 слайдов, ответы на пять вопросов чекпоинта, стадия, ограничения и снимки работающего прототипа в ПК-версии.

**[Открыть рабочий прототип](https://mvideo-attribute-ai.vercel.app/)**. Сервис доступен в браузере; JSON API вызывается по `POST /api/extract`.

## Пять вопросов чекпоинта

1. **Задача и пользователь.** Заполнить атрибуты из текстовых карточек, чтобы товар мог участвовать в фильтрах и сравнении. Основной пользователь прототипа — модератор каталога; продавец может видеть результат при загрузке.
2. **Требования и ограничения.** На входе только текст и поля продавца. Значение нормализуется, сверяется со справочником и подтверждается цитатой. Конфликты отправляются на проверку. Независимого gold и официального перечня полей для всех категорий пока нет.
3. **Сценарий.** Пользователь выбирает SKU или вводит карточку. Правила извлекают значения, сервис показывает статус и доказательство для каждого поля, а также JSON для API. Снимки интерфейса приведены на слайдах 6 и 7 брифа.
4. **Ценность.** Модератору проще разбирать спорные поля, продавец видит пропуски, а каталог получает основу для более полного поиска. Прирост продаж пока не измерялся.
5. **Метрики.** Precision, recall, F1 и coverage считаются отдельно по атрибутам на независимой разметке. Отдельно нужны срезы редких категорий и продавцов; вес по трафику потребует данных об использовании фильтров.

## Какую задачу решаем

Незаполненные характеристики мешают товару попадать в фильтры и сравнение, а ошибочные значения искажают каталог. Основной пользователь — специалист каталога или модератор, который проверяет спорные атрибуты. Продавец может увидеть результат при подготовке карточки; покупатель получает пользу через более полный поиск.

## Что уже работает

- Браузерный интерфейс и JSON API для одной карточки: название, описание, поля продавца и необязательная категория.
- Правила и словари для явных полей, нормализации распространённых цветов, единиц измерения и отдельных систем размеров.
- Для каждого атрибута выводятся значение, цитата из карточки, поле-источник, метод, эвристическая уверенность и статус `accepted`, `review` или `missing`.
- В интерфейсе доступно 110 SKU из предоставленного архива; подготовлен пакет JSON-предсказаний для 1 177 200 текстовых SKU.
- Прототип и API проверены на смартфоне, ноутбуке, чайнике, футболке и контрольных карточках с пропусками и конфликтами; 8 из 8 автоматических тестов правил проходят.

Архив содержит 1 177 200 текстовых SKU, 546 069 предложений с параметрами каталога и 30 991 350 строк кликов запрос–SKU. В таксономии 6 963 категории. Эти числа описывают данные и масштаб обработки, а не качество извлечения.

## Стадия и ограничения

Это работающий прототип, а не завершённая продуктовая оценка. Проверка обязательных полей смартфона и ноутбука реализована по примерам из задания. На SKU 30079343 пять обязательных полей смартфона приняты, а модель направлена на проверку из-за конфликта записей. Независимого human gold и официального списка обязательных полей для всех категорий в архиве нет. Поэтому precision, recall и F1 по атрибутам пока не заявляются. Клики без показов и событий фильтров не позволяют оценить CTR или влияние на GMV. Экспериментальная ML-модель цвета не развёрнута в основном потоке; LLM-адаптер предусмотрен, но не настроен. Русские и английские варианты типовых значений поддерживаются правилами; китайская карточка без структурированных полей остаётся ограничением.

Следующий этап — получить независимую разметку и официальный список полей, оценить качество по каждому атрибуту, редким категориям и небольшим продавцам, затем настроить пороги публикации и ручной проверки. Ключевая мера против ложных атрибутов уже действует: спорное или неподтверждённое значение не принимается автоматически.

На этом публичном чекпоинте размещены README и PDF-бриф. Исходный архив карточек и производные выгрузки в публичный репозиторий не загружаются.
