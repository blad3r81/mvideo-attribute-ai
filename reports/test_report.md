Проверка заземления API на четырёх реальных SKU подтвердила, что у каждого принятого значения есть цитата в указанном поле входной карточки. Пакетный файл проверяется отдельно на количество строк и корректность JSON.

После изменений весь архив пересчитан тем же извлекателем: `data/predictions_full.jsonl.gz` содержит 1 177 200 корректно читаемых JSON-строк. У 373 436 карточек есть хотя бы одно принятое поле; 926 179 отдельных значений получили `accepted`, 5 587 098 направлены в `review`. Это технические статусы, не precision или recall. Рост числа `review` связан с тем, что значения без справочника допустимых вариантов больше не считаются надёжными только по наличию в поле продавца.

## Что пока не проходит как продуктовая оценка

- Gold precision/recall/F1 по каждому атрибуту: независимой ручной разметки в архиве нет.
- Подтверждение качества на длинном хвосте и у малых продавцов: их нужно включить в будущий gold-набор.
- Реальная точность LLM и рубли на карточку: внешний вызов не настроен, модель не используется в пакетной выдаче.
- CTR/GMV: в архиве нет показов, заказов и событий фильтров.

Эвристический балл `confidence` показывает приоритет проверки, но до калибровки не является вероятностью правильности. Поля `review` и `missing` не следует автоматически записывать в каталог.
