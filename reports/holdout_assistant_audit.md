# Фиксированный пример оценки 30 карточек

Дата: 23 октября 2026 года. Исходный код до просмотра результатов: `6a12a7f31e3365fdb13fe5316f452f7727d6bbc9`.

## Происхождение и пределы

Карточки взяты из исходного архива задания, не пересекаются со 110 SKU веб-демо. Отобрано по 10 SKU из категорий 761, 914 и 987. SHA-256 `data/holdout_cards.json`: `2bfbe8290b40d5c4fec18f70f607e137bccf87db334cce54d010818e28975773`. Все 190 обязательных полей заполнены ассистентом по тексту заголовка, описания и полей продавца **до запуска предсказаний**. SHA-256 `data/holdout_assistant_reference.json`: `1d02214a3a28f6cfe4e1a55e6a7ad6d55d0d8f0168ce4e192fe4812c7161e04c`.

Это не разметка независимого человека и не подтверждение качества на всём каталоге. Метрики ниже измеряют точное совпадение с этим примером. В частности, короткое каноническое название модели и длинная строка продавца считаются разными значениями; спорные случаи нужно согласовать с владельцем схемы и разметчиком. После просмотра ошибок этот набор не годится для независимой проверки новых изменений правил.

## Воспроизведение

```bash
node scripts/verify_reference.js
node scripts/predict.js data/holdout_cards.json data/holdout_predictions.json --rules-only
node scripts/evaluate.js data/holdout_assistant_reference.json data/holdout_predictions.json > reports/holdout_assistant_evaluation.json
node --test
```

`verify_reference.js` подтверждает 30 разных карточек, 190 заполненных полей, по 10 карточек на категорию и отсутствие пересечения с демо. Оценщик прерывается при отсутствующем или ошибочном предсказании, чтобы сбой не был принят за пропуск атрибута. Полный машинный отчёт находится в `reports/holdout_assistant_evaluation.json`.

## Разбор ошибок и следующих шагов

Часть несовпадений модели связана с разной гранулярностью: например, `Galaxy S25 Ultra` против `S25 Ultra`, а иногда в результат попадает длинное торговое название с памятью и цветом. Это показывает необходимость согласовать каноническое представление модели, но не даёт права менять его по одному тестовому набору. Цвета вне текущего проверяемого словаря остаются на ручной проверке, что снижает покрытие без выдумывания значений. Встречаются конфликтующие значения диагонали и цвета. Например, у SKU 400228693 описание и поле `_search` расходятся по диагонали, у SKU 400489984 — тоже, у SKU 400558740 не совпадает цвет. Для таких полей в эталоне стоит `null`.

На VM LLM реально участвует в обычном API пути при `LLM_AUTO_REVIEW=1`, но вызывается только для пропусков и спорных значений; правило не передаёт ей обработку каждого SKU. Проверка 22 октября на восьми категориях дала восемь успешных вызовов и 47 проверок спорных полей без новых предложений. Это подтверждает интеграцию, но пока не доказывает рост качества или сокращение ручной работы. Пакетная выгрузка большого каталога намеренно остаётся на правилах из-за цены вызовов.

23 октября повторный запуск на VM завершил 50 из 50 тестов, в том числе тест ограниченного пакетного вызова LLM через локальный mock-сервер. Отдельная живая проверка двух карточек через публичный API выполнила два вызова LLM и 30 проверок спорных полей, новых предложений не дала. Для запуска проверки использовался предоставленный организаторами шлюз; ключ не включён в репозиторий.

В тот же день пакетный путь проверен на всех 30 карточках через реальный шлюз. При тайм-ауте 8 секунд выполнено 30 попыток: 9 завершились, 21 вернула `unavailable`. Завершённые ответы дали 32 проверки спорных полей и ни одного нового допустимого значения. F1 автоматических атрибутов остался 0,796: LLM не меняет их без независимой калибровки и подтверждения. Результат расчёта сохранён в `reports/holdout_hybrid_evaluation.json`. Затем на пяти вызовах проверен тайм-аут 30 секунд: все пять завершились, дали 38 проверок спорных полей и ноль новых значений. Остальные 25 карточек в этом коротком опыте получили `quota_exceeded` по заданному лимиту, а не из-за сбоя. Пакетный тайм-аут по умолчанию увеличен до 30 секунд; интерактивный путь остаётся отдельным. Это проверка работы ветки и отказоустойчивости, а не подтверждение роста точности или уменьшения ручного труда.

На странице VM счётчик дневного расхода после опыта показывал 11,21 ₽ против 1,77 ₽ до него. Разница за этот период 9,44 ₽, но страница не даёт разбивки по запросам и не исключает параллельные вызовы, поэтому это не измеренная цена одной карточки.

Для независимого результата нужны новые, ранее не просмотренные карточки, два разметчика для спорных полей и единое определение канонических значений. Затем можно отдельно измерить правила и гибрид на одинаковом человеческом gold, а также зафиксировать цену на карточку и изменение доли ручной проверки.
