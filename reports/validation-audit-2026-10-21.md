# Проверка валидации и LLM на VM, 21 октября

## Почему подпункт получил 1,95 из 2

Сегодняшнее описание автопроверки на платформе признаёт схему вывода, справочники и проверки против выдуманных значений. Единственное названное замечание — отсутствие подтверждённого независимого gold-набора. Демо-карточки уже использовались при разработке и не являются таким набором. Ни дополнительный вызов LLM, ни автоматическая подстановка ответа сервиса вместо метки человека не устранят эту причину. Балл следующего прогона зависит от оценки организаторов и не гарантируется.

## Проверка рабочего пути

На командной VM протестированы 55 из 110 демо-карточек из 15 категорий, для каждой вызван `/api/preview` с `use_llm: true`. Отбор чередовал популярные и редкие SKU внутри каждой категории. Все 55 HTTP-запросов и все 55 вызовов GigaChat 3 Pro завершились. Ошибок источника для автоматически принятых значений и принятий ниже порога контрольный скрипт не нашёл. Ответ модели не принял ни одно поле автоматически. Это структурные проверки; истинность характеристик ими не доказана.

| Показатель | Результат |
| --- | ---: |
| Принятые атрибуты | 202 |
| Спорные атрибуты всех типов | 3 732 |
| Отсутствующие атрибуты | 8 |
| Обязательные поля без автоматического принятия | 20 |
| Проверки спорных полей от LLM | 444 |
| Предложения LLM для отсутствующих полей | 0 |
| Найденные нарушения точной цитаты и порога | 0 |
| Фактически списано за прогон | 16,65 ₽ |

Из спорных полей 3 529 требуют проверки допустимого значения, 201 содержит конфликт, 2 имеют несовместимые размеры. Многие из них дополнительные атрибуты; число 3 732 нельзя переводить в столько же действий модератора без исследования его рабочего процесса. Модель дала дополнительные пояснения, но на этой выборке не уменьшила число обязательных полей, переданных человеку. Средний наблюдаемый расход модели составил около 0,30 ₽ на карточку. Дневной расход команды после теста на странице VM: 18,36 ₽ из 300 ₽, ранее было 1,71 ₽.

## Подготовка независимой проверки

Скрипт `scripts/sample_holdout.py` отобрал из исходного архива 30 SKU, отсутствующих в 110 демо-карточках. Созданы 190 пустых заданий по обязательным полям смартфонов и ноутбуков. Метки должны проставить люди, видя только входную карточку и правила разметки. Желательно два разметчика на спорные случаи. Затем можно считать precision, recall, F1, coverage и частоту ложных автоматических принятий по каждому полю и категории. Выборку нельзя использовать одновременно для настройки порога и итоговой оценки.

После массового прогона выборочная проверка показала конкретный пропуск: у ноутбука SKU `30070420` обязательный накопитель оставался пустым, хотя поле продавца `Объём SSD: 512 ГБ` присутствовало. Добавлены варианты имени этого поля в словарь атрибутов. Значение теперь принимается с точной цитатой из поля продавца; регрессионный тест проверяет статус, число и источник. Это исправление не заменяет независимую проверку точности.

## Продуктовый вывод

Сервис защищает каталог от публикации неподтверждённых значений, но ценой большой очереди `review` по дополнительным полям. Для оценки экономии нужны время существующей модерации и время обработки результата сервиса. Для цены ошибки нужны показы, фильтры, заказы и исправления. Следующий эксперимент на разметке должен сравнить правила с гибридом по числу верных дополнений, ложных принятий, ручным минутам и рублям LLM. Пока говорить о росте продаж или об «идеальной» валидации нельзя.
