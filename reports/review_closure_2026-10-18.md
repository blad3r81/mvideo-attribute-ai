# Сверка с прогоном и заданием, 18 октября

## Исправления, которые можно проверить в коде

| Замечание прогона | Состояние и проверка |
|---|---|
| Доступ к API | Без `API_TOKEN` сервис теперь закрыт по умолчанию; публичность включается только явным `DEMO_MODE=1`. Тест `api-hardening.test.js`. На командной VM оставлен именно публичный демонстрационный режим. |
| Сбои и стоимость LLM | Таймаут и ограничение ответа, возврат к правилам при недоступном шлюзе. Квота учитывает только начатый вызов модели. LLM запускается по запросу и при наличии повода. |
| Входные данные и конфигурация | Ограничения тела, типов и длины; неизвестный ID категории отклоняется. Есть `.env.example`. Пути к каталогу, карточкам и статистике настраиваются. |
| Демо-зависимость | Новая схема категории может задать `required` и `allowed_values`; тест `new-category-schema.test.js` проверяет категорию, которой нет в демонстрационном архиве. Скрипт пакетного прогона принимает путь к исходной выгрузке. |
| Длинный хвост | Вне известных правил допускается только значение из справочника категории с подтверждением в тексте. Иначе `review`. Для новой категории поддержаны варианты написания канонического значения. |
| Пользовательский сценарий | UI показывает смысл статусов и доказательства, позволяет подтвердить или отклонить кандидата и выгрузить решения отдельно от исходного JSON. |
| Измерение качества | Добавлены подготовка ручной разметки по категориям, проверка её полноты, метрики по атрибутам/категориям/продавцам, macro F1, калибровка и вес по частоте кликов. На синтетическом эталоне тест показывает правильность расчёта, но не качество модели. |

## Что нельзя объявить закрытым без новых данных

1. В архиве нет независимого gold-набора. Поэтому реальные precision, recall, F1, калиброванная уверенность, равенство качества редких и частых категорий и продавцов остаются неизвестными.
2. Нет официального полного перечня обязательных атрибутов по категориям и справочников всех допустимых значений. Сервис принимает их из внешней схемы, но не выдумывает их.
3. В данных нет показов, событий фильтрации, заказов, времени работы модераторов и тарифной информации по шлюзу. CTR, GMV, цена ошибки в рублях и стоимость модели на карточку не измерены. `traffic_rows` является только прокси частоты.
4. Лимит запросов LLM хранится в памяти одного процесса. Для нескольких экземпляров нужен общий счётчик; текущая VM использует один экземпляр. Демо с `DEMO_MODE=1` открыто намеренно; закрытый API проверяется отдельно.

## Соответствие исходному заданию

- Вход только текстовый: название, описание и атрибуты продавца. Категория необязательна. Фото не обрабатываются.
- Значения имеют нормализацию, источник, метод, доказательство, балл и статус. Балл до независимой калибровки является эвристикой, а не вероятностью.
- Правила и словари выполняют основной поток. ML цвета проверен отдельно на silver-метках; LLM используется для сложных случаев, проверяет текст и не публикует сомнительное значение автоматически.
- Конфликты, диапазоны вместо точного числа, неизвестные значения и отсутствие обязательного поля не превращаются в принятые характеристики.
- Пакетный экспорт и API используют общий извлекатель. Выход для 110 реальных SKU хранится в репозитории; полный выход воспроизводится из исходного архива и не помещён в Git из-за размера.
- Успех будет оцениваться по каждому атрибуту, категории и продавцу на отдельной ручной разметке, а также по coverage и частоте запрос–SKU. Пока достоверных чисел качества нет.

## Проверка обновления на VM

Локально и внутри Docker на VM прошли 32 теста из 32, включая новую категорию в LLM-пути. После пересборки контейнера проверка `/api/health` вернула `ok`. Сквозной сценарий `scripts/vm_acceptance.js --llm` завершился с `passed: true`: 15 проверок, четыре вызова LLM и 100 из 100 успешных запросов при параллелизме 10. В этой короткой нагрузке p95 составил 47 мс. Это проверка работоспособности конкретной VM, а не подтверждение готовности к промышленному трафику.
