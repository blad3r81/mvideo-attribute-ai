# Дополнительная разметка и проверка качества, 24 октября 2026 года

Из исходного архива отобраны 12 карточек: по четыре из категорий 761, 914 и 987. Их SKU не встречаются в демонстрационных 110 карточках и первом размеченном наборе из 30 карточек. SHA-256 исходных текстов `data/holdout_second_cards.json`: `d9d895421305f496616409e02643d5a83f9d0494faaff187d2b139d927229c2`. По заголовку, описанию и текстовым полям продавца ассистент заполнил 76 обязательных значений, включая `null` там, где подтверждения нет или источники спорят. Разметка записана **до первого запуска предсказаний**. SHA-256 `data/holdout_second_reference.json`: `b8c6fad08a1d1e6d9cab1b5c9f038627ecfba71485e5c1cb119c14a83038ce2d`.

Это внутренняя разметка команды с помощью ассистента. Она **не является независимым human gold**. После первого расчёта ошибки на этих карточках использовались для правок правил. Поэтому текущие метрики показывают, как работает изменённая версия на уже просмотренных примерах, и не оценивают её качество на новых SKU.

## Повторить расчёт

```bash
npm run verify:reference:second
node --test
```

Команда проверяет полноту полей, отсутствие пересечений, заново запускает правила и печатает precision, recall, F1 по каждому атрибуту и категории. Полный JSON отчёт: `reports/holdout_second_evaluation.json`. Для фиксации нового отчёта можно перенаправить вывод `node scripts/evaluate.js data/holdout_second_reference.json data/holdout_second_predictions.json` в файл. Значения сравниваются с нормализацией регистра, пробелов и `е/ё`; это не нечёткое сопоставление товаров.

## Что получилось

| Версия на этих 12 карточках | Precision | Recall | F1 |
|---|---:|---:|---:|
| До разбора ошибок | 0,763 | 0,672 | 0,714 |
| После исправлений, текущий код | 0,908 | 0,881 | 0,894 |

Для текущего кода F1 модели равен 0,727, процессора 0,857, цвета 0,706, накопителя и ОЗУ 1,000. По категориям: 761 — 0,936; 914 — 0,944; 987 — 0,816. В каждой категории всего четыре SKU, поэтому эти доли нестабильны. На первых 30 карточках текущий F1 равен 0,846. Нельзя складывать эти два результата и выдавать среднее за оценку независимого каталога.

Исправлены три наблюдаемые ошибки: слово «сердце» не распознаётся как серый цвет; укороченное поле `Модель_search` не подменяет `Pixel 10 Pro` моделью `Pixel 10`; объём памяти и частота процессора не входят в канонические названия модели и процессора. Для принятого значения в JSON сохраняется исходная цитата. Тесты защищают эти случаи от повторения.

Пример действительно грязных данных: у SKU `401249650` заголовок и поле продавца говорят о Lenovo, а большая часть описания рассказывает о другом ноутбуке Acer. Для спорных полей внутреннего эталона выбран `null`; сервис ещё принимает часть признаков Lenovo. Это остаётся риском ложного автоматического заполнения. У восстановленного iPhone `30088630` заголовок говорит «серый титан», а поле производителя — `Natural Titanium`; цвет также оставлен без эталонного значения. Эти случаи полезны для показа маршрута на проверку, но не для заявления безошибочности.

Следующая проверка качества должна использовать новые SKU и согласованную разметку человека, не показанную разработчику до фиксации кода. До неё `confidence` остаётся эвристической оценкой, а денежный эффект и сокращение ручной работы не измерены.
