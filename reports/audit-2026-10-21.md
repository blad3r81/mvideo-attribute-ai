Текущее место в таблице не доказывает разницу в качестве самого извлечения: при разнице технической оценки 0,05 балла могут влиять правила сортировки равных результатов и ещё не выставленные баллы финальной защиты.

## Изменение в коде

Генератор заданий для разметчика больше не вызывает извлекатель, чтобы определить перечень полей. Перечень берётся только из схемы категории и обязательных полей кейса. Новый режим `required` создаёт компактный набор для смартфонов и ноутбуков; режим `all` сохраняет широкий анализ. Извлечение карточек, формат ответа API, решение о принятии значения и интерфейс не изменены.

## Проверка после ручной разметки

1. Два человека независимо проверяют 57 полей по тексту девяти карточек; спорные значения согласуют. Отсутствующее в тексте значение отмечают `null`.
2. Экспортируют завершённые задачи через `scripts/gold_to_eval.js` и считают метрики через `scripts/evaluate.js` по уже сохранённым предсказаниям.
3. Публикуют размер выборки, качество по каждому обязательному полю, число пропусков и ошибки. Девять карточек дают только предварительную оценку; для устойчивой оценки по всем категориям нужна отдельная расширенная выборка.

До этих шагов precision, recall, F1 и выгода от LLM на редких значениях не заявляются. Повышение балла или места после публикации этого исправления не гарантируется.
