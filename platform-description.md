# Описание решения для платформы

## Что делаем

Мы создаём сервис для заполнения характеристик товаров в каталоге М.Видео. Продавцы присылают карточки с названием, описанием и своими полями. Важные сведения часто спрятаны в тексте, записаны в разных единицах или противоречат друг другу. Из-за пустых полей товар хуже находится через фильтры, а ошибочные значения портят результаты поиска.

Сервис извлекает характеристики, приводит их к общему виду и показывает доказательство для каждого значения. В ответе есть источник, метод, оценка уверенности и статус. Подтверждённое значение можно принять, спорное передать модератору, отсутствующее оставить пустым. Результат виден в браузере и доступен через JSON API.

## Как устроено и какой стек

Основной путь начинается со справочника категорий, правил и словарей. Они обрабатывают явные поля продавца, распространённые цвета, единицы памяти, диагональ и другие типовые характеристики. Затем сервис проверяет, что значение присутствует во входной карточке и не конфликтует с другими записями. Отдельный эксперимент с ML-моделью цвета пока не включён в основной поток. Адаптер LLM предусмотрен для сложных пропусков, но сейчас не настроен; предложения модели должны проходить проверку по тексту и оставаться на ручной проверке.

Интерфейс написан на HTML, CSS и JavaScript. API и основной пайплайн работают на Node.js. Для подготовки большого архива и эксперимента с моделью используются Python, PyArrow, DuckDB и scikit-learn. Демо опубликовано на Vercel. Есть автоматические проверки на Node.js.

## Что уже успели

Работают веб-интерфейс и API. Можно выбрать один из 110 реальных SKU из предоставленного архива или ввести свою карточку. Сервис показывает нормализованные атрибуты, цитату, источник, метод, уверенность и статус, а также формирует JSON. Пакетный прогон подготовил результаты для 1 177 200 SKU. На смартфоне SKU 30079343 пять обязательных полей приняты, а модель отправлена на проверку из-за несовпадающих записей. Автоматические тесты правил проходят 8 из 8. Эти результаты показывают работоспособность сценария, но не заменяют оценку точности на независимой разметке.

## Что осталось

Нам нужен официальный перечень обязательных полей по категориям и набор карточек, размеченных людьми. На этом наборе мы посчитаем precision, recall, F1 и coverage отдельно для каждого атрибута, редких категорий и продавцов. После этого можно настроить пороги автоматического принятия и ручной проверки и проверить, как улучшение каталога влияет на поиск. В архиве есть клики, но нет показов и событий фильтров, поэтому CTR и рост продаж сейчас не заявляем.
