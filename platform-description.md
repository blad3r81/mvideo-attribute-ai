# Описание решения для технического чекпоинта, 23 октября

## Что сделали

Мы разрабатываем сервис для заполнения характеристик товаров в каталоге М.Видео. Продавцы передают название, описание и собственные поля в разном формате. Важное значение может остаться внутри текста и не попасть в структурированное поле. Тогда товар сложнее найти через фильтры. Обратная ошибка тоже существенна: неверная характеристика приводит покупателя к неподходящему товару и требует исправления карточки. Денежную цену этих ошибок мы пока не называем, поскольку у нас нет замера времени модерации, событий фильтрации и конверсии.

Сервис принимает только текстовые поля, определяет обязательные атрибуты категории, извлекает кандидатов, нормализует единицы и варианты записи, затем сопоставляет значения со справочником. Для каждого результата он показывает исходную цитату, источник, метод, числовой балл правил и статус. Надёжное значение может быть принято, конфликт или пропуск остаётся на проверке. Вывод доступен в веб-интерфейсе и в JSON для интеграции. Неподтверждённое значение автоматически не записывается в карточку.

## Как устроено и какой стек

Ядро и HTTP API написаны на Node.js, интерфейс на HTML, CSS и JavaScript. Для подготовки данных и экспериментов используются Python, PyArrow, DuckDB и scikit-learn. Приложение запускается локально и в Docker на командной VM; публичное демо доступно по адресу VM. В репозитории есть схема категорий, правила и словари, пакетный экспорт, EDA, проверки входа и тесты.

Основной быстрый путь опирается на правила и справочники. Для пропущенных и спорных полей на VM подключён шлюз LLM организаторов. Ответ модели сверяется с точной цитатой исходной карточки и допустимыми значениями; предложение без доказательства остаётся на ручной проверке. В пакетной команде число платных вызовов ограничивается параметром. Если модель недоступна, результат правил сохраняется. Мы не отправляем в LLM все 1,17 млн SKU: стоимость такого шага пока не оправдана измеренным приростом качества.

## Что успели проверить

Работают веб-интерфейс, API и пакетный вывод. В демо доступны 110 SKU из переданного архива, можно ввести собственный текст. Для всего набора подготовлен пакет предсказаний по 1 177 200 SKU. На VM проходят 50 автоматических тестов, а фиксированный пример из 30 карточек и 190 обязательных полей позволяет воспроизвести расчёт precision, recall, F1 и coverage по атрибутам и категориям. На разметке, выполненной ассистентом до просмотра предсказаний, F1 правил составляет 0,796. Это диагностический пример, не независимый human gold и не оценка качества всего каталога. Слабее всего на нём обрабатываются модель, цвет и процессор.

LLM проверена на реальном шлюзе. При коротком тайм-ауте пакетный опыт дал 9 завершённых вызовов из 30; пять пробных вызовов с тайм-аутом 30 секунд завершились все. Пакетный тайм-аут увеличен, при этом сохраняется лимит вызовов и безопасный возврат к правилам. Новых допустимых значений эта проверка не дала, поэтому роста F1 от LLM мы не заявляем.

## Что осталось

Для независимой оценки нужны новые карточки, согласованное каноническое представление спорных значений и разметка людьми. Затем сравним правила и гибрид на одном эталоне, отдельно по редким категориям и небольшим продавцам. Также измерим время обработки карточки, долю исправлений, цену вызова модели и пользу для фильтров. Этих измерений в доступных данных пока нет.

После утреннего стоп-кода командный Gitea архивирован и не принимает новые push. Код, который был в `main` к моменту стоп-кода, остаётся официальной версией для проверки.
